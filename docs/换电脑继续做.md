# 换电脑继续做

这份是给「换一台机器接着干活」用的，五步搞定。

---

## 一、拿到源码

源码包里已经有完整的 git 历史，解压后不需要重新初始化仓库。

```bash
# 解压到任意目录
unzip 博客改造-源码-2026-09-11.zip -d storm-site
cd storm-site
```

如果从 GitHub 直接拉：

```bash
git clone https://github.com/huangpuyuan/huangpuyuan.github.io.git storm-site
```

## 二、装依赖

需要 **Node 22 或更高**。

```bash
node -v     # 确认版本
npm install # 约 1 分钟，需要联网
```

依赖只有 Astro 和它的几个官方集成，没有别的。

## 五、改完发布

```bash
# 双击 publish.bat，或者
node scripts/publish.mjs
```

它会构建、提交、推送。GitHub Actions 收到推送后自动构建发布，1 到 2 分钟生效。

### 如果推送失败

按顺序检查：

1. **remote 配了吗**
   ```bash
   git remote -v
   ```
   应该看到 `origin  https://github.com/huangpuyuan/huangpuyuan.github.io.git`。没有就补：
   ```bash
   git remote add origin https://github.com/huangpuyuan/huangpuyuan.github.io.git
   ```

2. **登录了吗**
   首次推送会要求认证。推荐装 GitHub CLI（`gh auth login`），比配 token 省事。

3. **分支名对不对**
   ```bash
   git branch -M master
   ```

## 六、Pages 那个设置只改一次

打开 https://github.com/huangpuyuan/huangpuyuan.github.io/settings/pages

不改的话，推送上去也不会自动发布。

## 几个别忘的约定

1. **站内链接一定带结尾斜杠**，用 `postUrl()` / `tagUrl()` 拼，别手写
2. **动态生成的元素，样式用 `:global()`**，否则会静默失效
3. **`public/lab/` 里的归档文件只做加法**，不改内容
4. **`public/.nojekyll` 不能删**，删了线上样式全丢

详细背景见 `docs/项目文档.md` 第八节。
