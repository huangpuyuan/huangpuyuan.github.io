## 一、这是什么

一个**纯静态的个人主页**。把 7 年前那个 Jekyll 站重写了一遍，同时把散在四个独立仓库里的早年内容合并进来，一个站点管全部。

站点分四块：

| 板块 | 内容 | 规模 |
|---|---|---|
| 主页 | 自我介绍、最近笔记、作品、读诗 | 1 页 |
| 笔记 | 研究、数据、经济学、AI、学习心得 | 17 篇 |
| 实验室 | 早年写的项目，原样托管 + 重写的索引页 | 4 个板块 |
| 关于 | 经历、技能、联系方式 | 1 页 |

构建产物 **45 个页面**，加上实验室里原样托管的 **78 个归档 HTML**，一共 123 个 HTML 文件。

## 二、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | **Astro 5** | 默认输出零 JavaScript，只有需要交互的地方才挂脚本 |
| 内容 | Content Collections | Markdown + zod 字段校验，构建时报错 |
| 样式 | 原生 CSS + CSS 变量 | 没有引入任何 CSS 框架，样式写在各自的组件里 |
| 公式 | remark-math + rehype-katex | 老笔记里的 LaTeX 正常渲染 |
| 代码高亮 | Shiki | 构建时高亮，运行时零开销 |
| 页面跳转 | ClientRouter + 视口预取 | 接近单页应用的体验，但仍是静态文件 |
| 部署 | GitHub Actions → GitHub Pages | 推送即自动构建发布 |

**全站零外部依赖**：字体走系统字体栈，图标是内联 SVG，JS 库全部本地化到 `public/lab/vendor/`。

## 三、换电脑后怎么跑起来

```bash
# 1. 解压源码包，进目录
cd storm-site

# 2. 装依赖（首次，约 1 分钟，需要联网）
npm install

# 3. 本地起服务
npm run dev          # 开发模式，改完即时刷新 http://localhost:4321
node scripts/preview.mjs   # 构建 + 预览 http://localhost:8080
```

想直接发布：

```bash
# 双击 publish.bat，或者
node scripts/publish.mjs
```

它做三件事：构建 → 提交 → 推送到 GitHub。推上去之后 GitHub Actions 自动构建发布，1 到 2 分钟生效。

> **前提**：GitHub 仓库的 Settings → Pages 里，Source 必须选 **GitHub Actions**（不是 `Deploy from a branch`）。这个设置只需要改一次。

## 六、内容怎么加

### 写一篇笔记

在 `src/content/blog/` 新建一个 `.md`，文件名就是 URL 里的 slug。

```markdown
---
title: 文章标题
date: 2026-09-11
category: 笔记
summary: 一句话摘要，列表页和搜索结果显示这句。
---

正文用 Markdown 写。公式用 $行内$ 和 $$独立$$。
```

`draft: true` 可以暂时不上线。

### 加一篇数据结构讲解

在 `src/content/ds/` 新建 `.md`：

```markdown
---
title: 栈
order: 1
summary: 列表页和页头显示的一段话。
gist: 后进先出。数据只在顶部进、顶部出。
complexity:
  - 入栈 O(1)
  - 出栈 O(1)
chapter: 第 3 章 栈
demo: hash/UsingHash.html      # 可选，相对 public/lab/datastructures/
source: stack/stack.js         # 可选
---
```

`order` 决定顺序，索引页的编号和「上一篇 / 下一篇」都跟着走。`demo` 和 `source` 指向的文件如果不存在，链接会自动不渲染，不会出现死链。

### 改站名、导航、首页内容、作品列表

只动 `src/config.ts` 一个文件，里面是全站唯一的配置源。

## 七、设计系统

配色、字体、间距全部定义在 `src/styles/global.css` 里，以 CSS 变量的形式存在，深色模式靠切换 `data-theme` 属性整体换值。

| 变量 | 用途 |
|---|---|
| `--bg` / `--bg-elev` / `--bg-sunken` | 三层背景（页面 / 卡片 / 凹陷区） |
| `--fg` / `--fg-muted` / `--fg-faint` | 三级文字 |
| `--line` / `--line-strong` | 分割线与描边 |
| `--accent` / `--accent-soft` | 主色（链接、选中态、聚焦环） |
| `--ember` / `--ember-soft` | 警示色（过期、删除） |
| `--radius` / `--radius-sm` / `--radius-lg` | 圆角档位 |
| `--shadow-sm` / `--shadow-lift` | 阴影档位 |
| `--font-mono` | 等宽字体（标签、时间、编号） |

改配色只改这一处，全站生效。

## 八、三条硬规矩

这三条都是踩过坑之后写下来的，改代码前值得先看一眼。

### 1. 站内链接必须带结尾斜杠

构建用的是 `build.format: 'directory'`，`/blog/xxx` 实际落在 `/blog/xxx/index.html`。**少写那个斜杠是真的会 404**，不是「浏览器会自动补上」这么轻松。

```html
<a href="/blog/">列表页</a>
<a href="/blog/open-banking/">文章详情</a>
```

不要在模板里手拼，用 `src/utils/format.ts` 里现成的两个函数：

```ts
import { postUrl, tagUrl } from '../utils/format';
postUrl(post.id)    // /blog/<id>/
tagUrl(category)    // /tags/<slug>/
```

### 2. 运行时生成的元素，样式必须用 `:global()`

Astro 的 `<style>` 会编译成 `.cls[data-astro-cid-xxxx]` 这种形式，那个属性只加给**模板里写死的元素**。用 `innerHTML` 或 `createElement` 拼出来的元素拿不到属性，**对应样式会静默失效，一个字都不报错**。

```css
/* 对：挂在模板里的父元素下面，既能命中又不会外泄 */
.tasks :global(.task) { display: flex; }

/* 错：编译成 .task[data-astro-cid-xxx]，动态生成的 .task 匹配不上 */
.task { display: flex; }
```

### 3. `public/lab/` 里的归档文件只做加法

那些是 2017 年的原始文件，原则是不改内容。只允许三件事：换掉失效的 CDN 引用、加「回实验室」浮标、注入控制台输出镜像。要改内容请改索引页或讲解页。

## 十、部署

```
本地 git push
   ↓
GitHub Actions（.github/workflows/deploy.yml）
   ↓ npm ci → npm run build → upload-pages-artifact
   ↓
GitHub Pages
```

**唯一需要手动做的设置**：仓库 Settings → Pages，把 Source 从 `Deploy from a branch` 改成 `GitHub Actions`。改完之后每次推送 `master` 分支就自动发布。

> 注意：`public/.nojekyll` 必须保留。少了它 GitHub Pages 会忽略 `_astro` 目录，整站样式全丢。
