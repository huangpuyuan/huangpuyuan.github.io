## 三、定下来的规矩

### 站点的规矩（会一直管着后面的改动）

**三条硬规矩**，都是踩过坑写下来的：

1. **站内链接必须带结尾斜杠。** 构建用 `build.format: 'directory'`，`/blog/xxx` 实际落在 `/blog/xxx/index.html`。少写斜杠**真的会 404**，不是「浏览器会自动补上」。别在模板里手拼，用 `src/utils/format.ts` 的 `postUrl()` / `tagUrl()`。
2. **运行时生成的元素，样式必须用 `:global()`。** Astro 的 `<style>` 编译成 `.cls[data-astro-cid-xxxx]`，那个属性只加给模板里写死的元素；`innerHTML` / `createElement` 拼出来的拿不到，**样式静默失效，一个字都不报错**。
3. **`public/lab/` 里的归档文件只做加法。** 那是 2017 年的原文件，原则是不改内容。只允许三件事：换掉失效的 CDN 引用、加「回实验室」浮标、注入控制台输出镜像。要改内容请改索引页或讲解页。

另外几条：

- 站名、导航、作品列表、实验室条目集中在 `src/config.ts`，改一处生效，别散在模板里
- 内容一律走 Content Collections（`src/content/blog/`、`src/content/ds/`），放进去就自动有列表页、分类页、RSS、搜索
- 改完必须跑验收脚本，不靠肉眼

- 迭代式反馈，一次说一点，我改完你再提下一条

## 四、几个关键决策，和为什么

**为什么换 Astro**
站点是纯静态托管在 GitHub Pages，不需要服务端。Astro 默认输出零 JS，只有搜索面板、任务清单、讲解页目录这几处按需加载脚本；同时它自带 Content Collections，文章有了 schema，字段写错构建直接报错，比 Jekyll 裸写 front matter 可靠。

**为什么文章从 `reverie` 搬进 `src/content/blog/`**
原来文章散在仓库里、格式各一。搬进来之后统一了 front matter 和渲染链路，增删文章不再需要动模板，分类页和搜索也自动跟着走。

**为什么 `public/lab/` 只做加法**
那是 2017 年的学习痕迹，价值就在「原样」。改了内容就没法跟当年对照了，而且 78 个归档页面的 CDN 引用早就全挂了——修引用是必须的，改内容是另一回事。

**为什么任务清单要重写**
原版是 jQuery 的，为了一个单页清单拖着三个依赖。改成原生 JS 后依赖清零，交互测试也才能用真实点击跑起来。

**为什么数据结构讲解引用 2017 年的原源码**
讲解和演示页要对得上。引用新写的示例代码，读者打开演示页会对不上号。所以八篇讲解里贴的代码全部来自 `public/lab/datastructures/` 里那份原文件。

## 五、踩过的坑（按价值排序）

细节和修法见 `docs/重构总结-2026-09-11.md` 第五节，这里只留教训。

**1. 你报的那个 bug：文章点不开**
链接写成 `/blog/open-banking`，少了结尾斜杠。要命的不是这个 bug，是**它跑了那么久测试却全绿**——断言只看了 `location.pathname`，跳 404 页时地址栏照样是对的。
→ 教训：断言要检查**页面渲染出来的东西**，不是 URL。

**2. 动态元素的样式会静默失效**
`innerHTML` 拼出来的元素拿不到 Astro 的作用域属性，样式不生效且不报错。现象是「排版看起来怪怪的但控制台干净」，最难查。
→ 教训：只要元素是运行时生成的，样式一律 `:global()`。

**3. `astro dev` 和 `astro preview` 行为不一致**
dev 会自动帮你把 `/about` 转成 `/about/`，preview 直接 404。
→ 教训：「dev 里能打开」不能当验收标准，链接写完要用 `lint-links` 扫。

**4. 78 个归档页面的 CDN 全挂了**
2017 年的 CDN 地址早就不可用，页面白屏。全部改指本地 `vendor/` 才有得看。

**5. `lint-links.mjs` 一直返回退出码 1，没法当门禁**
4 条 2017 年就缺文件的链接是历史遗留，不是新问题。加了 `KNOWN_BROKEN` 白名单单独报出来、不计入退出码，脚本才真正能用。
