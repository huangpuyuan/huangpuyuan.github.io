## 一、变量、数据类型与堆栈

### 命名约定

笔记开头记了两个"命名风格"的例子——用符号前缀模拟命名空间：

```javascript
jQuery      // $.each()
underscore  // _.each()
```

`$` 和 `_` 都是合法标识符，用它们做库的全局入口，既短又不容易撞名。当年把这个当"技巧"记下来，现在看其实是**用最少字符抢占一个全局命名空间**的朴素做法。

另外要避开关键字和保留字：`if`、`for` 之类，别拿来命名。

### 基本类型 vs 引用类型

这是理解 JS 的**第一道分水岭**：

| | 基本类型（Primitive） | 引用类型（Reference） |
| --- | --- | --- |
| 存储位置 | **栈内存** | **堆内存** |
| 能否修改 | 不能被修改 | 可以被修改 |
| 相等比较 | 值相等即相等 | 需指向**同一个引用**才相等 |

原笔记写得很精炼：

> - 基本类型 不能被修改
> - 引用类型 可以被修改，比较时指向同一个引用才相同
> - 栈内存：有序、不能扩展、放基本类型
> - 堆内存：无序、能扩展、放引用类型

这里有个初学者最容易混淆的点：**基本类型"不能被修改"不是指变量不能重新赋值**，而是指**值本身不可变**。你写 `var a = 1; a = 2;` 并没有"修改"那个 `1`，而是让 `a` 指向了一个新的值 `2`。对象不一样：

```javascript
var obj1 = { name: "kaitai" };
var obj2 = obj1;
obj2.name = "xixi";
console.log(obj1.name); // "xixi" —— obj1 也被改了！
```

因为 `obj1` 和 `obj2` 存的是**同一个堆地址**。这就是当年练习里 `script.js` ~ `script3.js` 反复验证的东西。

## 二、Chrome 调试工具

第二篇笔记是**调试面板全景图**——2017 年 Chrome DevTools 的五大面板：

### 1. 审查元素（Elements）

- 查看页面源代码、查看**被 JS 动态改变**的 DOM（右键元素 → 动态改样式/属性/内容）
- 支持直接编辑整段 HTML
- 可以查看页面上绑定的**事件监听器**（当年是 Event Listeners 面板，现在叫 Event Listener Breakpoints）
- 模拟器：切换成移动设备视口调试

### 2. 网络监听（Network）

- 查看页面**全部资源**的网络请求详情：耗时、状态码、请求头
- **Ajax 返回的 JSON 自动格式化**查看（这个当年超实用）
- 支持按请求类型分组过滤（XHR / JS / CSS / Img...）
- 查看页面完全加载的总耗时、总请求数

### 3. 静态资源（Sources）

- 网页加载的所有静态资源都在这里
- **注意**：如果文件加载失败（比如路径写错），它**不会出现**在资源列表里——当年排查"JS 没生效"时就靠这条
- 按路径归类整理
- **断点调试**的主战场（下面详述）

### 4. 控制台（Console）

- JavaScript 日志输出，不同级别显示不同颜色（`log` / `warn` / `error` / `info`）
- 数据输出、直接写表达式验证结果
- **动态执行代码时，定义的变量都是全局变量，上下文有关联性**——上半行定义的变量，下半行能直接用
- 断点停留时查看当前变量值

### 5. 本地存储（Application）

只能查看**当前域名**下的存储数据，三类：

```javascript
// Cookie —— 有有效期，过期日期小于当前日期则自动删除
document.cookie;

// LocalStorage —— 长期保存，无截止有效期，容量约 5MB
// 用来存储不变化的数据，减少网络请求
localStorage.setItem("key", "value");

// SessionStorage —— 关闭浏览器（标签页）之后就没了
// 用户当前操作的数据
sessionStorage.setItem("key", "value");
```

| 存储 | 生命周期 | 容量 | 典型用途 |
| --- | --- | --- | --- |
| Cookie | 有有效期，到期自动删 | ~4KB | 登录凭证、会话标识 |
| LocalStorage | 长期，除非手动清 | ~5MB | 不变的数据、缓存，减少网络请求 |
| SessionStorage | 关闭标签页即失效 | ~5MB | 当前操作态、临时数据 |

## 三、断点调试（这是重点）

### 基本操作

- **增加断点**：在 Sources 面板里点行号，出现蓝色标记
- **停用断点**：再点一次，变灰
- **单步执行 / 跳过**

### 查看变量值的三种方式

当年特意记下来，因为调试时最常做这个：

1. **鼠标滑过**变量名——最快，适合临时看一眼
2. **控制台直接输入变量名**——能拿到实时值，还能做运算
3. **右键 → Add to Watch**——选中变量加入监视列表，单步过程中一直显示

第 3 种在追踪一个变量怎么被一路改坏的时候最好用，因为不用每步都去 hover。

### 快捷键速查

| 操作 | 快捷键 | 说明 |
| --- | --- | --- |
| 唤醒程序 / 跳过断点 | `F8` | Resume script execution，直接跑到下一个断点 |
| 单步执行 | `F10` | Step Over，把函数调用当成一步，不进函数体 |
| 进入函数体 | `F11` | Step Into |
| 跳出函数 | `Shift + F11` | Step Out |
| 禁用所有断点 | `Ctrl + F8` | Deactivate breakpoints，不删断点但全停用 |

区别 `F10` 和 `F11` 是**理解调用栈的关键**：`F10` 把 `foo()` 整个当一步（不关心里面怎么跑），`F11` 钻进去逐行看。

### 其他

- 断点管理：支持**部分启用/停用**、全部移除
- **本地代码支持动态修改**——改完断点还能保留，当年改一行试效果的效率就靠这个
