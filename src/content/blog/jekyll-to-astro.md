七年前我用 Jekyll 搭了这个主页，之后它就基本没动过。最近把它整个重写成了 Astro 静态站：45 个页面、零外部依赖、43 项自动化测试、推送即部署。过程本身不复杂，但踩到的三个坑值得单独写一篇——每一个都不是"报错然后修好"，而是**系统性地骗过了我的检查手段**。

## 0 为什么动它

旧站的账单：Ruby + Jekyll + Node + gulp 四套构建环境、4 个外部 CDN（其中 Google Fonts 在国内根本打不开）、内容散在 4 个仓库（主页、笔记站、前端练习、数据结构练习）、改一个站名要翻 6 个 include 文件。

重构后的形态：

| 项 | 旧 | 新 |
|---|---|---|
| 构建环境 | 四套 | 只要 Node |
| 外部 CDN | 4 个 | 0 个 |
| 内容仓库 | 4 个 | 1 个 |
| 测试 | 无 | 43 项（20 冒烟 + 21 交互） |
| 部署 | 手工推文件 | 推送自动构建 |

一个原则贯穿始终：**早年写的东西一律不动，只做加法**。2017 年的前端练习原文件原样托管在 `/lab/` 下，只换掉失效的 CDN 引用、注入一个返回浮标；笔记和索引页则全部重写。

## 1 坑一：测试全绿，文章全是 404

**症状**：笔记列表、首页文章卡片，点进去全部 404。地址栏是对的，页面就是打不开。

**根因**：链接写的是 `/blog/open-banking`，而构建配置用的是 `build.format: 'directory'`——页面实际生成在 `/blog/open-banking/index.html`。少了结尾那个斜杠，GitHub Pages 不会重定向到目录。

```
404  /blog/open-banking      ← 列表页点的就是这个
200  /blog/open-banking/     ← 多一个斜杠才对
```

而且是全站性的：导航里的 `/blog`、`/lab`、`about` 全中招。

**为什么 41 项测试没拦住**：冒烟测试的断言只检查了 `location.pathname`——跳到 404 页时地址栏照样正确，测试自然通过。这是典型的**假通过**：断言验证的是"去了哪"，而不是"看到了什么"。

**修复分三步**：

1. 链接统一收敛：`src/utils/format.ts` 里写 `postUrl()` 和 `tagUrl()`，全站 20 多处裸斜杠写法全部换掉
2. 配置收紧：`astro.config.mjs` 明确 `trailingSlash: 'always'`
3. 测试升级：导航断言改成**检查目标页的正文渲染出来没有**——404 页从此无法蒙混过关

另外 `lint-links.mjs` 新增一类检查：链接目标是个目录但没写结尾斜杠，构建时直接报错。现在这件事有三道关卡兜着。

## 2 坑二：Astro 作用域样式对动态元素静默失效

**症状**：任务清单页面第一版，列表项排版彻底散掉——复选框、正文、按钮竖着堆叠，像是 CSS 全丢了。但检查器里样式规则明明都在。

**根因**：Astro 的 `<style>` 编译产物是：

```css
.task[data-astro-cid-unyx5r4r] { display: flex; }
```

这个 `data-astro-cid` 属性只加给**模板里写死的元素**。任务列表是 JS 里 `innerHTML` 拼出来的，拿不到这个属性，选择器永远匹配不上。**而且一个警告都不报。**

在构建产物里能直接看出来：

```bash
grep -oE '\.task[^{]*\{[^}]*\}' dist/_astro/*.css
```

**修复**：动态生成的元素，样式用 `:global()` 挂在模板里真实存在的父元素下面：

```css
.tasks :global(.task) { display: flex; }   /* 命中，且不外泄 */
.task { display: flex; }                    /* 永远匹配不上动态元素 */
```

顺带用同样的思路修好了搜索面板一个一直没查出原因的老毛病——`.palette__item` 那组也是动态建的，之前表现为标题和分类黏在一起。

**防回归**：因为这类 bug 是静默的，只能靠视觉断言兜底——冒烟测试里加了两条排版断言，直接读 `getComputedStyle` 和元素的相对位置。

## 3 坑三：触摸设备上永远点不到的按钮

任务清单里"详细 / 删除"按钮原本靠 `:hover` 才显示。桌面鼠标没问题，但触摸设备没有 hover——**按钮永远出不来，功能等于不存在**，而桌面测试全绿。

```css
@media (hover: none) {
  .task__actions { /* 触摸设备上常显 */ }
}
```

这类问题的共性是：**测试环境本身就是有偏的样本**。我所有测试都在桌面 Chrome 里跑，hover、精确点击、大屏幕，全是默认假设。

## 4 验收清单

| 项 | 结果 |
|---|---|
| 构建 | 45 页，零警告 |
| 路由 | 关键路由与演示页全部 200 |
| 冒烟测试 | 20 / 20 |
| 任务清单测试 | 21 / 21 |
| 死链扫描 | 1101 条站内引用，4 条为 2017 年原代码遗留 |
| 响应式 | 6 档视口无横向溢出 |

## 5 三条经验

1. **断言要验"结果"而不是"动作"**。"跳转成功"和"目标页正文渲染出来了"是两件事，后者才防得住 404 假通过
2. **静默失效比报错危险得多**。作用域样式这类问题框架不提示、不警告，唯一防线是视觉回归
3. **测试环境是一种偏见**。只在桌面 Chrome 里跑测试，等于默认所有用户都有鼠标和 hover
