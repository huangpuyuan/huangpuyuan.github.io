## 它解决什么问题

有一类问题，公式推起来很麻烦，但**用随机数掷很多次就能出答案**。比如：

- 掷两个骰子，点数和是偶数的概率是多少
- 随机试 1000 万次密码，能撞上原来那个吗
- 从一堆数里取平均，重复做 100 万次，这些均值会落在哪

这类方法叫**蒙特卡洛模拟**。它的思路很朴素：不去推导精确公式，而是真的模拟很多次，用「出现频率」去逼近「真实概率」。

代价是需要跑很多次，所以特别挑语言性能。这正是 Julia 的用武之地——写起来像 Python 一样顺，跑起来接近 C。当年就是拿这几个小脚本练手的。

## 四个脚本

这份笔记里有四个脚本，从概率计算到性能对比，难度递增：

| 脚本 | 在算什么 | 用到的东西 |
|---|---|---|
| `dice.jl` | 两个骰子点数和为偶数的概率 | 数组推导式、蒙特卡洛 |
| `password.jl` | 随机密码撞中真实密码的概率 | 大数模拟、概率上界 |
| `monte-carlo.jl` | 中心极限定理的实证 | 分位数、性能对比 |
| `plot-function.jl` | 画函数和它的导数 | 绘图、极值 |

## 一个贯穿全部的想法

这四个脚本其实在做同一件事：**用「大量重复」来替代「复杂推导」**。

掷骰子那个，精确解只要数一下 36 种组合就够了；但密码那个，精确计算已经很难，模拟反而简单。所以蒙特卡洛真正的价值不是算得准，而是**当你不知道公式长什么样时，它仍然能给你一个答案**。

当然，代价是精度。模拟出来的值有误差，误差量级大约是 `1/√N`——想多要一位精度，就得跑一百倍的次数。这就是为什么这类方法对语言性能如此敏感。

## 运行方式

需要先装 Julia，然后进到脚本目录直接跑：

```bash
julia scripts/dice.jl
julia scripts/password.jl
julia scripts/monte-carlo.jl
```

`plot-function.jl` 需要额外两个包：

```bash
julia -e 'using Pkg; Pkg.add(["Plots", "LaTeXStrings"])'
julia scripts/plot-function.jl
```
