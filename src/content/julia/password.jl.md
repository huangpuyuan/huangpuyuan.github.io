## 问题

设一个 8 位的密码，字符集是大小写字母加数字，一共 62 种。随机猜：

- 猜中**完整密码**的概率是多少？
- 如果攻击者能看出**有几位猜对了**（很多早期系统会这么提示），猜 1000 万次能蒙中多少？

第一个问题是小学组合题。第二个问题才是这个脚本要讲的。

## 密码空间有多大

```julia
const PASS_LENGTH = 8
const CHARS = collect('a':'z') ∪ collect('A':'Z') ∪ collect('0':'9')
```

`collect('a':'z')` 把字符区间展开成数组，`∪` 是并集运算符——这是 Julia 里直接当运算符用的数学符号，不用敲 `union()`。三个区间并起来，`length(CHARS)` 是 **62**。

于是密码空间是：

```julia
@printf("密码空间 = %d^%d ≈ %.2e\n", length(CHARS), PASS_LENGTH, Float64(length(CHARS))^PASS_LENGTH)
```

输出 `62^8 ≈ 2.18e+14`，也就是 **218 万亿**种组合。暴力枚举肯定不现实——按每秒 10 亿次算，也要跑 2.5 天。

## 关键在那句「有几位猜对了」

真正的问题不在密码空间，而在于**反馈**。

如果系统只告诉你「密码错了」，那攻击者只能全量枚举。但如果系统告诉你「8 位里有 3 位是对的」，攻击就被拆解了——每一位可以**单独**攻破。

这个脚本模拟的就是这种弱化后的场景：

```julia
num_match(candidate) = sum(candidate[i] == CORRECT[i] for i in 1:PASS_LENGTH)
```

逐个字符比对，数出相同的位置有几个。然后只要**猜中至少 1 位**就记一次命中：

```julia
matches_needed = 1
```

## 先算个理论值

「至少猜中 1 位」这件事，反面是「一位都没猜中」。某一位置上猜不中的概率是 `1 - 1/62`，8 位全不中就是它的 8 次方：

```julia
theoretical = 1 - (1 - 1/length(CHARS))^PASS_LENGTH
```

**这类"至少……"的问题，一律先取反面。** 因为「至少中一位」的情况要拆成"中 1 位 + 中 2 位 + ……"来加，而反面只有一种情况，好算得多。

算出来是 **0.121978**。

## 再真掷 1000 万次

```julia
function hit_count(rng, n, needed)
    hits = 0
    for _ in 1:n
        candidate = String(rand(rng, CHARS, PASS_LENGTH))
        if num_match(candidate) >= needed
            hits += 1
        end
    end
    return hits
end
```

`rand(rng, CHARS, PASS_LENGTH)` 从 CHARS 里**有放回**地抽 8 个字符，返回一个 `Vector{Char}`，外面套 `String()` 变成字符串。

实测结果：

```
字符集大小            = 62
密码空间              = 62^8 ≈ 2.18e+14
至少猜中 1 位的理论值 = 0.121978
蒙特卡洛 10000000 次  = 0.122109  （命中 1221088 次）
耗时                  = 1.11 秒
```

模拟值 0.122109 和理论值 0.121978 只差 0.0001，**1000 万次循环 Julia 跑了 1.11 秒**。

## 那个软作用域坑

写这个脚本的时候踩了一个 Julia 特有的坑。原本的写法是把循环直接铺在顶层：

```julia
hits = 0
for _ in 1:10^7
    ...
    hits += 1     # ← 这里会炸
end
```

跑起来报错：

```
Warning: Assignment to `hits` in soft scope is ambiguous because a global
variable by the same name exists: `hits` will be treated as a new local.
ERROR: UndefVarError: `hits` not defined
```

原因是 Julia 的**软作用域**规则。像 `for`、`while`、`try` 这些结构本身**不引入硬作用域**——在脚本顶层（REPL 里）写循环，循环体里的变量按理说能改到外面的全局变量。但 Julia 规定：**如果循环体里对一个已存在的全局变量赋值，这个变量会被当成新的局部变量**，于是 `hits += 1` 变成在读一个还没定义的局部变量，当场报错。

这是 Julia 从 0.x 到 1.0 期间反复讨论的设计取舍：既要 REPL 里敲代码方便，又不想让脚本里的变量泄漏成全局。

修法很简单——**把循环包进函数**：

```julia
function hit_count(rng, n, needed)
    hits = 0
    for _ in 1:n
        ...
        hits += 1     # 函数体是硬作用域，hits 就是普通局部变量
    end
    return hits
end
```

函数体是**硬作用域**，没有歧义。顺带还有个好处：**函数里的循环编译器优化得更狠**，比顶层脚本快不少。所以「把计算包进函数」在 Julia 里不只是躲坑，本身就是性能建议。

## 结论

| | 数值 |
|---|---|
| 密码空间 | 62^8 ≈ 2.18 × 10^14 |
| 至少猜中 1 位的理论概率 | 12.20% |
| 1000 万次模拟命中率 | 12.21% |

注意这两件事**不矛盾**：

- 猜中**完整**密码的概率是 `1/62^8 ≈ 4.6 × 10^-15`，天文数字般小
- 猜中**至少一位**的概率是 **12%**，一点都不小

差别的根源就是**反馈粒度**。前者要一次性对上 8 位，后者只要对上 1 位。

这也是为什么真实系统做了这些事：限制尝试次数、加延迟、锁定账号、不透露"对了几位"。**密码强度不只看长度，还要看攻击者能拿到多少信息。**

## 关于精度

模拟值 0.122109 比理论值 0.121978 高了 0.00013。这属于正常波动——蒙特卡洛的误差量级是 `1/√N`，N = 10^7 时约 `0.0003`，偏差落在范围内。

想更准就得跑更多次，而**精度每提高一位，次数要翻一百倍**。这就是为什么这类模拟才需要一门跑得快的语言。
