## 它解决什么问题

有一类需求，特征都是「记住最近发生的事」：撤销上一步操作、判断括号有没有配对、把十进制转成二进制。这些场景要的不是随便存取，而是**最后放进去的东西，最该被先拿出来**。

栈就是为这个特征造出来的。它把「只能在一端操作」这条限制写死，换来的是不需要记任何位置，拿到的永远是最新的那个。

## 生活里长什么样

食堂窗口那摞餐盘。只能从最上面拿，洗干净的新盘子也只能摞在最上面。想拿最底下那个，得先把上面全搬走。

浏览器的后退按钮是同一个道理。依次访问 A、B、C 之后，后退先回到 B，再回到 A。最后去的页面最先离开。

## 一步步写

### 第 1 步 定好容器和规矩

用数组存，但只允许在**末尾**动。为什么是末尾不是开头，倒数第二步会说。

```js
function Stack() {
    let items = [];
}
```

`items` 放在函数体里当私有变量，外面拿不到。这样谁也没法绕过 `push` / `pop` 直接改数组，栈的规矩才守得住。

### 第 2 步 入栈

```js
this.push = function (element) {
    items.push(element);
};
```

数组的 `push` 本来就是往末尾追加，正好对上「只往顶上摞」。

### 第 3 步 出栈

```js
this.pop = function () {
    return items.pop();
};
```

这里比数组的 `pop` 多做了一件事：**把删掉的那个返回出去**。数组的 `pop` 本来就返回被删元素，直接透传就行。这一点很关键，返回不了的话数据就拿不到了，栈等于白建。

### 第 4 步 看一眼栈顶，但不拿走

```js
this.peek = function () {
    return items[items.length - 1];
};
```

`pop` 是拿走，`peek` 是只看一眼。判断括号配对时经常要先看再决定，所以这个方法跑不掉。

### 第 5 步 补上几个状态判断

```js
this.isEmpty = function () {
    return items.length == 0;
};

this.size = function () {
    return items.length;
};

this.clear = function () {
    items = [];
};
```

`isEmpty` 值得单独写一个方法，不要到处写 `size() === 0`。空栈上 `pop()` 返回的是 `undefined`，不检查就往下算，错误会跑到很远的地方才暴露。

### 为什么动末尾不动开头

如果约定在开头进出，就得用 `shift()` 和 `unshift()`。这两个方法每执行一次，都要把数组里剩下的元素整体挪一格。数据少的时候无所谓，多了就是肉眼可见的慢。

这就是「只在末尾动」的价值：一次操作只碰一个元素，跟数据总量没关系。

## 复杂度

| 操作 | 复杂度 | 为什么 |
|---|---|---|
| push | O(1) | 只碰数组末尾一个位置 |
| pop | O(1) | 同上 |
| peek | O(1) | 按下标直接取 |
| 查找某个值 | O(n) | 要挨个看一遍，栈不擅长这个 |

## 什么时候会用到

- 撤销、重做
- 判断括号或标签有没有配对
- 十进制转二进制：不断取余，余数倒着读
- 浏览器的前进后退历史
- 函数调用本身。递归太深报栈溢出，说的就是这个栈

## 容易踩的坑

- 空栈直接 `pop()`，拿到 `undefined` 还继续往下算
- 用 `shift` / `unshift` 代替末尾操作，写起来像对，实际每次都是 O(n)
- 把栈和队列弄混。区别只在从哪一头出去：栈是同进同出，队列是一头进另一头出
