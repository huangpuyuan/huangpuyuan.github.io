## 它解决什么问题

需要**按来的顺序处理**的时候。打印任务、消息投递、请求排队，都是先提交的先处理完。

栈反着来，队列顺着来。这两个结构放在一起看，差别小到只有一行代码，用途却几乎没有重叠。

## 生活里长什么样

奶茶店门口那条队。新来的站最后面，做好的从最前面走。中间谁也不能插。

## 一步步写

### 第 1 步 容器和约定

```js
function Queue() {
    let items = [];
}
```

约定两件事：**从末尾进，从开头出**。记住这个方向，剩下全是自然推导。

### 第 2 步 入队

```js
this.enqueue = function (element) {
    items.push(element);
};
```

跟栈的 `push` 一模一样，因为「新来的排最后」和「新盘子摞最上面」是同一个动作。

### 第 3 步 出队

```js
this.dequeue = function () {
    return items.shift();
};
```

这是队列和栈**唯一**的区别。栈出栈动末尾，队列出队动开头。`shift()` 把第一个元素拿掉并返回它，正好对应「最前面那个人的事办完了」。

### 第 4 步 看队首

```js
this.front = function () {
    return items[0];
};
```

和栈的 `peek` 是同一个角色，只是换到了开头。

### 第 5 步 剩下的几个

```js
this.isEmpty = function () {
    return items.length == 0;
};

this.clear = function () {
    items = [];
};

this.size = function () {
    return items.length;
};
```

## 复杂度

| 操作 | 复杂度 | 说明 |
|---|---|---|
| enqueue | O(1) | 往末尾加，一步到位 |
| dequeue | O(n) | `shift()` 要把后面的元素整体往前挪一格 |
| front | O(1) | 按下标取 |

`dequeue` 是 O(n)，这是这份实现里唯一的短板。数据量小的时候完全感知不到，一多就得换写法：

- 用两个下标指针标出队首和队尾，只在越界时才真的整理数组
- 直接用链表，头尾各留一个引用

这里保持了最短的写法，把复杂度问题留在这一节里说清楚，不提前优化。

## 什么时候会用到

- 打印队列、任务队列
- 消息队列的模型
- 广度优先搜索。图的遍历那一篇就靠它
- 节流、按顺序执行的异步任务

## 容易踩的坑

- 混淆 `shift` 和 `pop`。写错了队列就变成栈，行为完全不同
- 把优先队列当成普通队列。优先队列每次出队拿的是优先级最高的，不是最早进来的，实现是另一套东西（一般用堆）
